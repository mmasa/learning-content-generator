# リスク管理(Risk Management)

> ISO 9001 / ISO IEC 27001 の考え方を参考にした運用ルールです(認証・完全適合の主張ではありません)。

## 原則

1. Issue 作成時に Risks / Security Considerations 欄でリスクを識別する
2. 重大なリスクは個別 Issue として追跡する
3. リスク対応は「回避・低減・移転・受容」から選び、判断理由を記録する

## 主要リスクと基本対応

| リスク | 対応 |
| --- | --- |
| 著作権侵害(過去問・規格本文・有償資料の混入) | raw データのGit管理外化、出典記録必須、レビューでの権利確認 |
| 秘密情報の漏えい(APIキー・個人情報) | pre-commit / CI での検出、コミット禁止ルール、インシデント手順 |
| AI生成物の誤り(誤答・不正確な解説) | 人間レビュー必須、問題・正解・解説の整合チェック |
| AI利用コストの超過 | AI利用ログによるコスト集計と月次レビュー |
| 見積と実績の大幅乖離 | 見積差異の集計([継続的改善](continuous-improvement.md)へ入力) |
| 単一担当者への依存 | 手順の文書化、記録の構造化 |
| 依存ライブラリの脆弱性 | CI での pip-audit、依存更新の定期実施 |

## 運用

- 新しいコンテンツカテゴリ追加時は、著作権・ライセンス・データ分類のリスクを必ず評価する
- インシデント発生時は再発防止策とともにリスク一覧を見直す
- リスク見直しの記録は Issue または `reports/security/` に残す
