# 文書管理(Document Control)

> ISO 9001 の考え方を参考にした運用ルールです(認証・完全適合の主張ではありません)。

## 原則

1. 正式な文書はすべて本リポジトリの Git 管理下に置く(単一の情報源)
2. 文書の変更もコード同様に Issue / PR / レビューを経る
3. 版管理は Git 履歴で行い、別途の版番号管理は行わない
4. 廃止した文書は削除し、経緯は PR とコミット履歴に残す

## 文書体系

| 場所 | 内容 | 位置づけ |
| --- | --- | --- |
| ルート(README 等) | プロジェクト概要・参加規約 | 一次文書 |
| `docs/governance/` | 運用ルール(本書群) | 一次文書 |
| `docs/operations/` | 実務手順 | 二次文書 |
| `docs/specifications/` | データ・ログ仕様 | 二次文書 |
| `docs/templates/` | 記録様式のテンプレート | 様式 |
| Issue / PR / `reports/` | 実施記録 | 記録 |

## 記述ルール

- 文書は日本語、スキーマ・コード・記録のフィールド名は英語
- 他文書への参照は相対リンクで行い、リンク切れは CI(markdown lint)の対象とする
- 規格(ISO等)への言及時は「考え方を参考にした運用」であることを明記し、
  認証取得・完全適合と誤解される表現を使わない

## レビューと承認

文書の追加・変更は [review-and-approval](review-and-approval.md) に従う。
運用と文書が乖離した場合は、乖離を Issue 化しどちらかを修正する。
