# レビューと承認(Review and Approval)

> ISO 9001 の考え方を参考にした運用ルールです(認証・完全適合の主張ではありません)。

## 原則

1. すべての Pull Request は**作成者以外によるレビュー**を必須とする
2. AI が生成した変更であっても**自動承認しない**。AI生成物は必ず人間が
   内容・権利・正確性・安全性を確認する
3. レビュー記録(指摘・対応・承認)は PR 上に残し、監査可能にする

## レビュー観点(最低限)

- Issue との対応 / 要求事項との一致 / Acceptance Criteria の充足
- コード品質(lint・型・設計)/ テスト結果 / 再現性 / 後方互換性
- セキュリティ / 個人情報 / 秘密情報の混入有無
- 著作権・ライセンス / データ出典の記録
- AI生成箇所の明示 / AI利用記録 / トークン利用記録 / 工数記録
- ドキュメント更新の有無
- 生成コンテンツの正確性 / 読み上げ内容の自然さ / 問題・正解・解説の整合性

具体的なチェックリストは [PRテンプレート](../../.github/PULL_REQUEST_TEMPLATE.md) と
[content-review-checklist](../templates/content-review-checklist.md) を使用する。

## 個人開発時の暫定運用(自己レビュー)

複数人のレビュアーを確保できない期間に限り、次の条件をすべて満たす自己レビューを認める。

1. PR に**自己レビューであることを明記**する
2. 最初の生成・実装から**一定時間(目安: 12時間以上)を空けて**レビューする
3. レビューチェックリストを**すべて確認**する
4. AIによるレビューを補助として利用してよいが、**人間の確認を省略しない**
5. 複数人運用になった時点で、他者レビュー必須へ移行する(本節は廃止する)

## 承認とマージ

- 承認条件: CI がすべて成功し、レビュー観点の確認が完了していること
- 差戻しの場合は理由を PR に記録する(差戻し件数は品質統計の対象)
- マージ後に問題が見つかった場合は Rollback Plan に従う
