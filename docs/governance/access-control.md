# アクセス管理(Access Control)

> ISO IEC 27001 / ISMS の考え方を参考にした運用ルールです(認証・完全適合の主張ではありません)。

## 原則

1. 最小権限の原則: 作業に必要な最小限の権限のみを付与する
2. 権限の付与・変更・削除は記録を残す(GitHub の監査ログ+必要に応じ Issue)
3. 共有アカウントを使用しない

## リポジトリ権限

| ロール | 権限 | 対象 |
| --- | --- | --- |
| Owner / Maintainer | 設定変更、マージ、権限管理 | リポジトリオーナー |
| Contributor | ブランチ作成、PR 作成 | 承認された協力者 |
| AIエージェント | Contributor 相当(人間の運用者の権限内) | 運用者の責任で使用 |

## ブランチ保護

- main への直接 push を禁止する(ブランチ保護ルールを設定)
- マージには PR とレビュー承認を必須とする
- 管理者もバイパスを常用しない(緊急時は記録を残す)

## 認証・認証情報

- GitHub アカウントは 2FA を必須とする
- APIキー等の認証情報は環境変数 / ローカル `.env`(Git管理外)で管理し、
  用途ごとに分離、不要になり次第失効させる
- CI で必要な秘密情報は GitHub Actions Secrets のみで扱う

## 退任・棚卸し

- 協力者の離脱時は速やかに権限を削除する
- 権限と発行済み認証情報は少なくとも年1回棚卸しする
