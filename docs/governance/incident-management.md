# インシデント管理(Incident Management)

> ISO IEC 27001 / ISMS の考え方を参考にした運用ルールです(認証・完全適合の主張ではありません)。

## 対象

- 秘密情報(APIキー・トークン・個人情報)の誤コミット・漏えい
- 著作権上問題のあるデータの混入
- 不正アクセス・アカウント侵害の疑い
- CI/CD やリポジトリ設定の重大な誤り
- AI生成物による重大な誤情報の公開

## 対応フロー

1. **検知・報告** — Security Incident テンプレートで Issue を作成する。
   **秘密情報そのものは Issue に記載しない**
2. **初動** — 被害拡大の停止(認証情報の無効化、該当データの非公開化)を最優先で行う
3. **影響評価** — 漏えい範囲・影響するデータ分類・外部影響の有無を確認する
4. **恒久対応** — 原因除去(履歴からの除去を含む)、必要ならルール・CI の改修
5. **記録** — 時系列の対応記録を Issue に残し、完了後 `reports/security/` に要約を保存する
6. **再発防止** — [継続的改善](continuous-improvement.md)に従い改善 Issue を作成する

## 秘密情報を誤コミットした場合の必須手順

1. 該当の認証情報を**直ちに無効化・ローテーション**する(履歴削除より先に行う)
2. `git filter-repo` 等で履歴から除去し、強制 push の影響を関係者へ周知する
3. インシデント Issue に経緯を記録する

## 記録項目

発生日時 / 検知方法 / 影響範囲 / データ分類 / 初動対応 / 恒久対応 / 再発防止策 / 対応工数
